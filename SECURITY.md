# SECURITY.md — ProjectX Security Reference

This file is an internal reference for developers and AI coding assistants.
It defines the security model, auth flows, and coding rules that MUST be followed
to prevent security lapses — especially when working with AI-assisted development.

---

## 1. Authentication Flows

### Master Admin (`/master-admin`)
1. POST `/api/admin/login` — verify username against `MASTER_ADMIN_USERNAME` env var and bcrypt-compare password against `MASTER_ADMIN_PASSWORD_HASH`
2. On success: generate 6-digit OTP, store in Cloudflare KV under key `otp:<username>` with **5-minute TTL**, send via Twilio SMS to `MASTER_ADMIN_PHONE`
3. POST `/api/admin/verify-otp` — read KV, compare OTP, **delete KV entry immediately** (single-use), issue signed JWT as `HttpOnly; Secure; SameSite=Strict` cookie (8-hour expiry)
4. A separate non-HttpOnly `meta` cookie carries `{ role: "admin", display: "..." }` for UI rendering only — never trust this for authorization

### Wholesaler (`/dashboard`)
1. POST `/api/wholesaler/login` — bcrypt-compare against `wholesalers.password_hash` in D1, check `status = "active"`
2. Issue signed JWT as `HttpOnly; Secure; SameSite=Strict` cookie (24-hour expiry)
3. JWT payload: `{ sub: wholesalerId, role: "wholesaler" }` — nothing else

### Retailer (`/[token]`)
- No JWT. Identity is stored client-side in Zustand (`localStorage`) after the WhatsApp modal
- The `token` in the URL is validated server-side on every request by checking `dynamic_links` table: `token = ? AND expires_at > unixepoch()`
- Retailer data (name, shop, phone) is sent in the order POST body — never trusted from a cookie or header

---

## 2. JWT Rules
- Sign and verify using `jose` with `HS256` and `JWT_SECRET` (64-char random hex, set in Cloudflare Dashboard secrets — never in code or wrangler.toml)
- Always verify JWT on the Worker side before any protected route handler runs
- Never decode a JWT on the frontend and use it for access control — the Worker is the authority
- JWT expiry: Admin = 8h, Wholesaler = 24h
- On logout: clear both the HttpOnly JWT cookie and the meta cookie via `Set-Cookie: ...; Max-Age=0`

---

## 3. Secret Management Rules

### What goes in Cloudflare Dashboard secrets (NEVER in code or wrangler.toml)
```
JWT_SECRET
MASTER_ADMIN_USERNAME
MASTER_ADMIN_PASSWORD_HASH
MASTER_ADMIN_PHONE
TWILIO_ACCOUNT_SID
TWILIO_AUTH_TOKEN
TWILIO_FROM_NUMBER
```

### What goes in wrangler.toml (non-secret config only)
- D1 database binding + ID
- KV namespace binding + ID
- R2 bucket binding + name
- Cron trigger schedule

### What goes in .env.local (gitignored, frontend only)
```
NEXT_PUBLIC_API_URL=https://...workers.dev
```

### Hard rules
- Never log secrets, JWT values, OTPs, or password hashes — not even in dev
- Never commit `.env`, `.env.local`, or any file containing real credentials
- `.gitignore` must include: `.env`, `.env.local`, `.dev.vars`, `*.pem`, `*.key`
- When Claude generates code that reads a secret, it must read from `env.SECRET_NAME` (Cloudflare Worker env binding) — never hardcode a fallback value

---

## 4. Input Validation Rules
- Every Worker route that accepts a request body MUST validate it with a Zod schema via `@hono/zod-validator` before touching the database
- Never pass raw user input into a SQL string — always use Drizzle ORM parameterized queries
- Never use `db.run(sql)` with user-supplied SQL except in the Admin D1 Explorer, which is behind MasterAdmin JWT and should default to read-only mode
- Sanitize all text fields stored to D1 (trim whitespace, enforce max lengths in Zod schemas)
- File upload slots (R2): validate MIME type and file size in the presigned URL generator; reject anything that isn't `image/jpeg`, `image/png`, or `image/webp` and anything over 5MB

---

## 5. CORS Configuration
- The Worker's CORS middleware must only allow the exact Cloudflare Pages origin (`ALLOWED_ORIGIN` env var)
- Never use `Access-Control-Allow-Origin: *` on any authenticated route
- Credentials (`withCredentials: true`) must be set on all frontend fetch calls for cookies to be sent

---

## 6. Dynamic Link Security
- Tokens are generated using `crypto.randomUUID()` (Web Crypto API, available in Workers) with dashes stripped — 32 hex characters, cryptographically random
- `expires_at` is enforced server-side on every retailer request — client cannot bypass it
- Expired links are cleaned up by the daily cron worker; they also return 404 immediately if accessed
- Never expose the internal `wholesaler_id` in the storefront URL or public response — only return the minimum needed (businessName, catalog data)

---

## 7. R2 Image Upload Security
- Presigned PUT URLs are generated by the Worker (requires Wholesaler JWT)
- Presigned URLs expire in **15 minutes**
- The bucket is NOT public — all image reads go through a Worker proxy that validates the request
- R2 object keys follow the pattern: `wholesaler-{id}/product-{id}/slot-{1|2|3}-{uuid}.{ext}` — no user-supplied path components

---

## 8. Rate Limiting
- Auth routes (`/api/admin/login`, `/api/wholesaler/login`, `/api/admin/verify-otp`) are rate-limited using Cloudflare KV as a counter
- Limit: 10 attempts per IP per 15-minute window
- On exceeding: return `429 Too Many Requests` with a `Retry-After` header
- Counter key pattern: `ratelimit:<route>:<ip>`

---

## 9. Admin D1 Explorer Rules
- Accessible only behind a valid MasterAdmin JWT
- By default, runs queries in a simulated read-only mode: block any statement that starts with `INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `CREATE` unless the admin explicitly toggles "Allow Writes" in the UI
- Log every query run (timestamp, truncated SQL) to a KV audit log key: `audit:d1:<timestamp>`
- Never stream raw D1 error messages to the client — they may expose schema details

---

## 10. AI Coding Assistant Rules (Claude-specific)

When Claude (or any AI assistant) writes code for this project, it MUST:

1. **Never hardcode secrets** — always use `env.SECRET_NAME` for Worker code and `process.env.NEXT_PUBLIC_*` for frontend-safe vars only
2. **Always validate inputs** — every new Worker route must include a Zod validator; never skip it "for now"
3. **Never disable CORS** — do not widen `ALLOWED_ORIGIN` to `*` even temporarily for debugging
4. **Use parameterized queries** — never construct SQL strings by concatenating user input
5. **Preserve HttpOnly on auth cookies** — never suggest switching to `localStorage` for JWT storage
6. **Check expiry on dynamic links** — every route that serves retailer catalog data must go through the link middleware
7. **Never expose internal IDs in public routes** — the retailer-facing API must not leak `wholesaler_id`, `retailer_id`, or internal DB IDs in URLs or responses where they're not needed
8. **Ask before weakening security** — if a task seems to require relaxing a security control, flag it explicitly instead of quietly loosening it
9. **No `console.log` of sensitive data** — no logging of passwords, OTPs, JWTs, or phone numbers, even in dev/debug code
10. **No `--no-verify` git commits** — never skip pre-commit hooks; if a hook fails, fix the root cause
